## Integration decisions

The two reviewed trees conflict in four files: `src/client/inbox.tsx`, `src/inbox/host.ts`, `src/inbox/service.ts` under `packages/personal-agent`, and `tests/client/inbox.spec.tsx`. Selecting one side would remove either the draft controls, desktop controls, or an acceptance path. The candidate preserves both UI/test groups and requires both runtimes to drain before storage closes, including startup failure cleanup.

Owner result acceptance keeps distinct requirements. A configured draft task requires its existing exact effect/receipt verification path. A local or leased desktop task requires a released native Worker and cannot bypass a required receipt. Every accepted result still requires the current policy, sealed artifacts and no unsettled effects. Cross-kind starts are denied. Existing schema v16, mobile approval, media, model routing and budget checks are retained; no migration was added or renumbered.

A new native same-host regression enables the reviewed GitHub draft path and real isolated Chromium together. It holds the browser's readiness request, then prepares, approves, dispatches, reads back and accepts a separate draft while the browser remains in flight. After releasing the page, the browser saves its own value and its result can also be accepted. Attempting to turn the prepared draft into desktop work is denied; preparing a draft on the running browser task is denied. The GitHub provider in this case is controlled, so it does not establish real GitHub connector acceptance.
