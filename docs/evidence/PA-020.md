## Implemented boundary

- Today lets the authenticated owner propose a project-scoped Markdown template after choosing at least two distinct accepted task results. The immutable revision records exact task and artifact versions, content digests, required text fields, Markdown output and the `render-markdown` capability. Example artifacts stay in their original tasks. The owner authors the template and fixtures.
- A held-out case has its own accepted task artifact and explicit inputs. Cases cannot share tasks with examples or reuse an example's expected output bytes. Evaluation renders each case and compares the output hash with the verified artifact digest. Approval pins the revision digest and the current selection version and requires every case to pass.
- The owner runs the active revision explicitly. The renderer substitutes bounded strings once and returns local Markdown as literal text. The skill has no tool, plugin, scheduling, notification, memory or model dispatch path. Acceptance and corrections are counted by revision. Run replay is fenced by revision, operation ID and input digest. A previously approved revision remains available for rollback while its evidence is current.
- Inspection, evaluation, activation, rollback and reuse recheck the exact verification and artifact, provenance exclusions and current source authorization. Invalid evidence hides the affected specification and blocks use. The private work database stores revision inputs for fixtures, evidence references and feedback. It stores digests for new run inputs and keeps the resulting text in the response. Schema 012 preserves earlier records and creates an owner-private v11 backup.
