## Device and replay

- WorkStore issues an owner/profile-scoped one-use pairing code with a five-minute lifetime. A successful enrollment atomically replaces the code digest with a digest of a separate 30-day credential. The database stores digests and device metadata. Revocation and expiry remove device authority on the next check. The restore path clears old pending and active credentials from the restored copy.
- The transport-independent feed authenticates each snapshot and replay. It projects conversation-linked tasks from the existing WorkStore and replays up to 128 committed events after a scoped cursor. A missing, foreign or stale cursor requires a fresh snapshot. Events expose task ID, version, status and time. Snapshots omit session identities, source destinations, private constraints and artifacts.
- The pinned DSH Web connection maps its browser credential to a shared owner Peer. Exact Fetch routes require that owner Peer. The existing inbox also binds an approval to an exact client, device and session. These boundaries inform the separate mobile admission and explicit approval handoff still needed. ## Mobile HTTP and Web

Commit `d833b4a21a49c56641ae1cda2a021d87b4cd76b6` wires the ledger and feed into an opt-in loopback HTTP listener. The operator's dedicated HTTPS origin terminates TLS at a reverse proxy. The upstream validates Host, Origin and Fetch Metadata, and pairing sets an independent secure, HttpOnly, SameSite=Strict cookie. The native local owner uses Today to issue a pairing code and revoke devices.

The separate responsive page reads scoped snapshots and follows the SSE stream. An out-of-window cursor requests a fresh snapshot. The stream rechecks the device on each poll and closes on revocation. The mobile listener exposes only its own assets and pairing, snapshot and event routes.
