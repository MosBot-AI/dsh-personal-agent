## Device and replay

- WorkStore issues an owner/profile-scoped one-use pairing code with a five-minute lifetime. A successful enrollment atomically replaces the code digest with a digest of a separate 30-day credential. The database stores digests and device metadata. Revocation and expiry remove device authority on the next check. The restore path clears old pending and active credentials from the restored copy.
- The transport-independent feed authenticates each snapshot and replay. It projects conversation-linked tasks from the existing WorkStore and replays up to 128 committed events after a scoped cursor. A missing, foreign or stale cursor requires a fresh snapshot. Events expose task ID, version, status and time. Snapshots omit session identities, source destinations, private constraints and artifacts.
- The pinned DSH Web connection maps its browser credential to a shared owner Peer. Exact Fetch routes require that owner Peer. The existing inbox also binds an approval to an exact client, device and session. These boundaries determine the separate mobile admission path and the explicit approval handoff. ## Mobile HTTP and Web

Commit `d833b4a21a49c56641ae1cda2a021d87b4cd76b6` wires the ledger and feed into an opt-in loopback HTTP listener. The operator's dedicated HTTPS origin terminates TLS at a reverse proxy. The upstream validates Host, Origin and Fetch Metadata, and pairing sets an independent secure, HttpOnly, SameSite=Strict cookie. The native local owner uses Today to issue a pairing code and revoke devices.

The separate responsive page reads scoped snapshots and follows the SSE stream. An out-of-window cursor requests a fresh snapshot. The stream rechecks the device on each poll and closes on revocation. The mobile listener exposes its own assets and pairing, snapshot, event and assigned approval routes. ## Exact mobile reviews

Commit `9373a93dd183b9a1ecba14adc816e4134b3845dc` adds versioned handoff to one enrolled device and recall by the original owner client. WorkStore v15 keeps the original approval binding and the assigned responder separately. The phone submits the expected version, digest and approve or deny decision to the existing exact-action gate. The gate checks current enrollment for a mobile grant and the coordinator still claims the original action at most once. The SSE approval hint carries no preview. The authenticated page retrieves exact cards over a separate request and provides a Web app manifest.
