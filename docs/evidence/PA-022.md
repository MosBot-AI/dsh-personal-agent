## Implemented checkpoint

- WorkStore issues an owner/profile-scoped one-use pairing code with a five-minute lifetime. A successful enrollment atomically replaces the code digest with a digest of a separate 30-day credential. The database stores digests and device metadata. Revocation and expiry remove device authority on the next check. The restore path clears old pending and active credentials from the restored copy.
- The transport-independent feed authenticates each snapshot and replay. It projects conversation-linked tasks from the existing WorkStore and replays up to 128 committed events after a scoped cursor. A missing, foreign or stale cursor requires a fresh snapshot. Events expose task ID, version, status and time. Snapshots omit session identities, source destinations, private constraints and artifacts.
- The pinned DSH Web connection maps its browser credential to a shared owner Peer. Exact Fetch routes require that owner Peer. The existing inbox also binds an approval to an exact client, device and session. These boundaries inform the separate mobile admission and explicit approval handoff still needed.
