## 已实现边界

- Worker 启动或引导会在同一 SQLite 事务提交确切 Attempt、代次、稳定原生消息标识、游标、渲染后的载荷与摘要。原生输入在 Session 刷盘并写入匹配的 SQLite 回执后才可进入推理。日志在后续观察中保留刷盘时间。
- DSH 冷读回核对无继承历史的 Session 头、目录、稳定修订、确切消息标识和摘要，并分页读取收件箱事件。它区分待处理、已进入模型、已取消、缺失及不明确的输入。已领取但缺少已提交用户消息的输入保持未知。缺少等效证据的旧记录继续等待对账。
- 启动时，在分类中断工作期间限制新的原生输入、动作领取和 Outbox 发送。无法核实的冷 Worker 按代次封锁，适用时保留确切等待引用。已有的确认释放证据可结算确切取消。启动分类结束后可开展新工作，已封锁的 Attempt 与不确定的交付继续受各自限制。
- 取消先持久化代次变更，再向所属原生工作发信号。过期报告、新输入意图和确认无法跨越退役代次。确切取消在结算前检查未决 Effect 和 Outbox 领取。
- Effect 与 Outbox 恢复保留原始领取，并使用限定范围的供应商读回。确切已知回执结算原记录，未知结果仍不确定。明确未发送证据可允许普通 Outbox 使用同键重试。一次性 Effect 领取继续保持已消费。
- 模式 004 保留既有工作，并在迁移时建立源版本备份。受控恢复入口将新的私有目标发布为持久的仅对账模式。恢复的授权与待发记录在重开后继续受限。限定范围的检查、撤销和精确读回仍可用。
