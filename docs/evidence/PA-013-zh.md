## 已实现的边界

- SQLite 在模型生成前以货币单位的百万分之一为整数单位，原子预留并领取所配金额上限。准入核对确切供应商与模型、当前 Task 和 Attempt、所有者 UTC 日、任务总额、次数及并发。自动请求要求已知价格或明确不计费。所有者手动启动的未知价格工作受调用次数及资源限制，其费用单独显示。
- 用量按领取时保存的价格核算，分别记录输入、输出、缓存读取和缓存写入计数。冷启动释放未领取的预留，并将中断的领取标为不确定。相应金额上限在跨 UTC 日期时仍计入预算，直到精确对账。Schema 006 创建私有 v5 备份，并保留路由、Worker 输入及恢复状态。
- 原生 Worker 生成和 Router 评估共用计量。Worker 禁用模型工具。输入、输出、轮次、步数和运行时间均有经过校验的上限。原生 Worker 遇到 429 后禁止自动重试。Worker 和 Router 在进程内共享确切路由的冷却状态，Worker 等待会持久记录可唤醒时间或无限期保留。冷却结束后，所有者可将已释放且满足条件的等待重新排队。前台控制使用独立路径。
- 进程内 GPU 队列默认一个重型槽位，并按 FIFO 有界排队。交接时检查 Task 和 Attempt。取消或超时会向作业发出停止信号，并保留实际槽位直到退出完成。
- 带版本的通知策略将日常进展合并到任务视图，并记录抑制或预留原因。主动 `off`、`observe`、`prepare` 和 `act` 各有独立决策。静默时段使用所选 IANA 时区。每位所有者每个本地日跨目的地最多预留三个主动通知。显式提醒和必要决策单独计数。一次性通知交接重新核对确切目的地、任务、策略和范围，然后调用同一存储的 Outbox。PA-007 仍负责路由、披露、FIFO 及供应商回执。
- 已认证收件箱展示计算与通知用量、不确定金额、队列占用、进展和最近决策原因。可选评估器缺少价格时，前台收件箱仍然可用。
