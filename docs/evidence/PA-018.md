## Implemented boundary

- The owner saves a draft and explicitly arms a versioned Routine. Editing or pausing advances the revision. SQLite separates Routine intent, exact native mapping, and the logical occurrence. The internal routine source is reserved against generic source binding and event intake.
- The bridge uses the pinned native calendar for Cron and delegates timed wakeups to native one-shot schedules. It records the IANA zone and DST policy that skips a gap and chooses the earlier overlap. The logical instant stays distinct from the physical wake, including a one-second creation lead. The `skip` policy allows one minute for a previously mapped wake to reach application reconciliation. The `latest` policy coalesces missed Cron slots and arms the latest logical occurrence for an exact wake.
- Mapping intent commits before native create. A complete, bounded native catalog can recover one exact marker, target and wake. Ambiguous, altered or missing bound records remain inspectable. A wake that elapses before the carrier calls native create is known unsent and can be retimed or skipped under policy. Exact obsolete active rows can be cancelled with the native revision check. Terminal native rows are retired after the application saves their receipt.
- A private mailbox accepts opaque wake markers with model and tool execution fenced. Application intake requires an exact ended native schedule and persisted receipt. The app deduplicates timed occurrences by Routine revision and intended instant. Explicit Run Now uses a separate command key. Stock Run Now receipts do not satisfy timed intake.
- Local reminders persist their original title and content and appear in the authenticated inbox. A goal occurrence checks the current authority, released Task wait, Attempt, version, generation and budget. It atomically commits the scoped source event, queue transition and occurrence. A denied budget records a skip and leaves the Task waiting. Either path uses zero Worker slots at admission.
- Schema 007 creates a private v6 backup and preserves budget, attention, Worker input and restore records. Reconciliation-only restore keeps the application dispatch gate closed.

## Slow-start recovery regression (#75)

[Issue #75](https://github.com/MosBot-AI/dsh-personal-agent/issues/75) isolates a fixture race found on main `96170a8`: the outside-edit test reused a native schedule due only 1,250 ms after creation. Its second real DSH process could start after that deadline, allowing native delivery before the fixture edited the row. On unchanged code, a 2,500 ms delay between `create-crash` and `recover-tampered` deterministically reproduced the failed `changed_native` assertion. Default and bounded-concurrency full suites reproduced it; standalone recovery could pass. This was not evidence that the Linux readiness PR changed schedule behavior.

The tamper test now uses its own creation phase with a 120-second future wake, beyond the bounded two-process test budget, and deliberately waits beyond the old short deadline before recovery. It asserts an active row and a successful native edit before reconciliation, then retains the invalid-row, zero-occurrence and uncertain-mapping assertions. The real crash/receipt recovery cases retain their short live timers. No production runtime, authorization or recovery logic changes; no global serialization, retry-until-pass, or weakened assertion masks the race.

Validation on Linux x86_64, Node.js 24.22.1 and pnpm 11.28.5: the six native schedule tests passed, including delayed tamper recovery. `pnpm check` passed type checking, build, all 329 tests and plan validation; a second default-parallel `pnpm test` again passed 329/329. The 12 coordination tests and `git diff --check` passed. Independent coordinating review checked that the original short-timer delivery scenarios and production runtime remain unchanged. This is test reliability maintenance, not new user-facing capability or expanded release acceptance.
