## Implemented boundary

- `ctx.dshpa.host.createWorkerExecutor()` coordinates one executor per work store. The default capacity is two Workers, with a validated range of 1–32. A trusted model-only preset binds provider, model, disclosure labels, and a real directory contained in its work root. Worker tools remain disabled. Foreground query, redirect, and cancellation use the current task scope while the slots are occupied.
- The executor reserves a slot and commits the Attempt's exact version, generation, session, directory, preset, and input cursor before opening the native Agent. Resume rechecks the persisted route, work directory, ownership, and empty native inbox. The Attempt retains up to 64 distinct input cursors across process restarts. Only Worker-minted message IDs and cursors enter the native model step.
- Reports are bounded JSON with the exact current cursor and one of `progress`, `waiting`, `blocked`, `ready`, or `failed`. The scoped observer selects the final text from the corresponding completed native turn. Progress remains observational. Dependency blocking checks the stored dependency chain. Readiness persists candidate artifact references and enters verification. The verifier should wait for native release before sealing evidence.
- A durable stop advances the generation before the executor signals the owned Agent. A durable wait keeps the slot through exact owned job and subagent cleanup, including late work observed during teardown. Unverified cleanup retains the slot. Cancellation settlement checks the Attempt's unresolved effects. The executor uses only trusted preset and coordinator inputs for these state transitions.

The coordinator commits the cursor and flushes native session events across two storage systems. The release check covers handles tracked by the current executor. PA-009 owns reconciliation for a crash between these writes, ambiguous provider outcomes, and recovery of work still marked running.
