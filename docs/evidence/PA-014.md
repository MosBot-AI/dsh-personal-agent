## Implemented boundary

- The authenticated inbox creates goal projects and edits plans at an exact revision. It records success criteria, milestones, review cadence, priority and rationale. Revision snapshots support reuse as editable drafts. Existing projects acquire a history baseline on first edit. Original creation commands remain replayable after plan edits.
- SQLite stores same-project prerequisites. The writer transaction rejects cycles, cross-project edges and stale Task versions. Verified prerequisite completion releases queued dependents when all their prerequisites are complete. Reopening a predecessor blocks queued dependents again. Native start and wake recheck the graph at admission. Already-running attempts keep their existing authorization.
- A native Worker can propose bounded subtask outcomes tied to its current Attempt and input cursor. The authenticated owner turns an exact draft into a new, sourced Task in the same project. Replay returns the same Task, and a subsequent Worker input supersedes the old draft.
- The on-demand weekly review orders active projects by priority and due time. It shows ready and waiting Tasks, upcoming milestones and recently verified results. It surfaces a priority decision only when equally ranked projects contend for an available Worker slot. Planning and review create no recurring schedule.
- Schema 010 adds project revisions, prerequisite edges and Worker drafts. Upgrading preserves WorkStore data and recovery mode and creates a private v9 backup.
