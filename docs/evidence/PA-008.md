## Implemented boundary

- The compiled Web extension contributes a **Today** main panel and sidebar entry through DSH slots. It uses DSH's existing Session navigation, transcript, and composer. Blocking questions and exact approval previews appear ahead of verified results and other work. English and Simplified Chinese copy comes from paired locale dictionaries.
- The host mounts an exact inbox route on the native Connection carrier when a local Web profile enables it. It requires loopback binding and the authenticated browser Peer. The tests distinguished that Peer from the separate API Peer carrying the same principal kind. A stable owner-private local binding scopes projects, tasks, artifacts, and approval responses. Request bodies have a 512 KiB application limit.
- The owner creates a project and attaches tasks to a known primary DSH Session. Start uses an explicitly configured Worker route and a task-specific workspace. Foreground pause, cancel, redirect, and answer go through deterministic scoped controls. Resume and answer require the exact wait or pause and known native release. Unknown runtime state remains visible. The UI retains unsent or unresolved drafts across connection changes and refreshes authoritative state.
- A model-only Worker can seal its bounded ready summary as a private Markdown candidate. The owner can download the exact bytes, then explicitly accept the result after native release. The existing verifier rechecks bytes, artifact scope, task version, and current owner authority before committing completion. Exact approval cards use the persisted digest and version.

This is a local owner surface. Connector routes remain trusted host composition, and PA-022 owns remote device enrolment and full reconnect security. PA-009 owns cold recovery when native release or cross-store input evidence is missing.
