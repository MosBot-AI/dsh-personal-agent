## 已实现的边界

- 所有者保存草稿后明确启用带版本的例行任务。编辑或暂停都会推进版本。SQLite 分开保存例行任务意图、精确原生映射和逻辑触发。内部例行任务来源保留给应用，通用来源绑定和事件准入会拒绝该身份。
- 调度桥通过固定版本的原生日历计算 Cron，将定时唤醒交给原生单次调度。保存 IANA 时区和夏令时策略，跳过缺失时刻并在重叠时选择较早时刻。逻辑时刻独立于实际唤醒时间，创建时预留一秒提前量。对已有映射的唤醒，`skip` 策略在应用对账时允许一分钟宽限。`latest` 合并错过的 Cron 时间槽，并为最近的逻辑触发设置精确唤醒。
- 在原生创建前提交映射意图。完整且有上限的原生目录用于找回唯一且精确匹配的标记、目标和唤醒时刻。歧义、篡改或绑定记录丢失时保留可检查状态。载体调用原生创建前已过期的唤醒可确认尚未发送，并按策略改期或跳过。过时的精确原生活跃项可按原生版本检查取消。应用保存回执后才清理已结束的原生记录。
- 私有收件会话只接收不透明唤醒标记，并限制模型与工具执行。应用准入要求原生调度已结束且持久化回执精确匹配。定时触发按例行任务版本和预定时刻去重。明确的立即运行使用独立命令键。原生界面的立即运行回执不能通过定时准入。
- 本地提醒保存原始标题与内容，并显示在已认证收件箱。目标任务触发核对当前授权、已释放的 Task 等待、Attempt、版本、代次及预算。限定范围的来源事件、排队转换和触发记录一并原子提交。预算拒绝会记录跳过，任务继续等待。两条路径在准入阶段均不占用 Worker 槽位。
- Schema 007 创建私有 v6 备份，并保留预算、通知、Worker 输入及恢复记录。仅对账恢复模式保持应用派发限制。

## 慢启动恢复回归（#75）

[Issue #75](https://github.com/MosBot-AI/dsh-personal-agent/issues/75) 隔离了主分支 `96170a8` 上发现的夹具竞态：外部修改测试复用了创建后仅 1,250 毫秒便到期的原生调度。第二个真实 DSH 进程可能在截止时刻之后才完成启动，导致夹具修改行之前已发生原生投递。未改动的代码中，在 `create-crash` 和 `recover-tampered` 之间等待 2,500 毫秒即可稳定复现 `changed_native` 断言失败。默认并发和限制并发的全套均复现，单独恢复测试却可能通过。这不能证明 Linux 就绪 PR 改变了调度行为。

篡改测试现使用独立创建阶段，将唤醒设在 120 秒后，超过有界的双进程测试预算，并刻意等待超过原来的短截止时刻后再恢复。对账前先断言行仍活跃且原生修改成功，随后保留无效行、零触发记录和不确定映射断言。真正的崩溃/回执恢复用例仍保留短期真实定时器。不改变生产运行时、授权或恢复逻辑；不通过全局串行化、重试至通过或削弱断言掩盖竞态。

验证环境为 Linux x86_64、Node.js 24.22.1 和 pnpm 11.28.5：六项原生调度测试通过，包括延迟后的篡改恢复。`pnpm check` 的类型检查、构建、全部 329 项测试和计划校验通过；第二次默认并发 `pnpm test` 再次通过 329/329。12 项协调测试及 `git diff --check` 通过。协调者独立审查确认原有短定时器投递场景及生产运行时保持不变。这是测试可靠性维护，不代表新增用户功能或扩大版本验收范围。
