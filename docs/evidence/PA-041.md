## Implementation

- The routing policy screens exact configured deployments for capabilities, context, data scope and Core admission before scoring the Task. Core supplies current destination authorization, account availability, quota and budget. The deterministic estimator uses task and phase signals, including scope, conflicting evidence and verification complexity.
- Versioned automatic rules select a pool and logical effort by tier. Low confidence uses a configured conservative floor. Fixed routes remain pinned, and a per-task override requires owner authority and an eligible policy pin. Automatic policies can explicitly allow omission of unavailable effort. Explicit effort selections require a valid mapping.
- Optional semantic estimation receives structured signals with separate input, output, spending and deadline limits. The Core admission port claims and deduplicates the Task and phase budget. The policy limits each estimate to one dispatch callback, discards late or invalid results, and rechecks admission before selecting a route.
- Escalation requires a trusted quality result from the same Task, attempt, policy and acceptance digest. It preserves approved requirements, checks the authoritative switch count, and requires a real increase in effort for the same deployment. Missing input and permission become waits.
