## 已实现的边界

- 可信适配器独立验证并绑定配置中的确切来源账户。准入层规范化事件，对规范化来源载荷计算摘要，并在 SQLite 中按来源实例、外部事件 ID 和不透明修订去重。载荷修改会产生冲突。升级后，旧版来源记录继续参与去重。
- 明确任务引用和精确的带版本工作订阅优先于语义评估。范围包括所有者、Profile、项目、来源实例、账户、线程和任务。匹配多条工作订阅时需要澄清。上下文订阅只记录关联。运行中任务按 Attempt 启动时间和订阅更新时间检查事件发生时间，事件唤醒按当前等待边界和精确引用检查。
- 路由输入将来源引用、任务转换、输入日志和路由回执一并提交。回执包含当前原生输入状态。原生推理前准入重新核对确切路由输入、当前订阅和有效授权。已经释放 Worker 的等待可在明确的可信唤醒策略下恢复同一 Attempt 和 Session。此前已准入的记录仍保留在原生 Session 中。
- Worker 退回事件时绑定当前 Attempt、代次、任务版本及已刷盘输入游标，只将原始事件交回评估一次。Worker 报告文本留在 Worker 边界内。启动时将中断的待路由事件、评估和退回记录标记为中断，避免重放。
- 语义评估在同一披露范围内将不同线程合并成批，在线程队列间公平轮转，限制待处理数量并设置期限。迟到的结果会被丢弃。缓慢的适配器在真正结束前继续占用原槽位。每个模型判断按事件 ID 独立校验，可以提出新任务或请求澄清，供所有者审阅。查询、改向和取消通过独立的前台路径处理。
- Schema 005 保留原有来源和 Worker 记录。升级 v4 时保存私有 `.v4.bak` 快照，保留既有恢复限制。本地 Web Profile 可加载可选的路由模型，已认证收件箱操作可管理订阅版本。
