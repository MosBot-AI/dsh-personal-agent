The release gate and its remaining acceptance are tracked on [PA-027](https://github.com/MosBot-AI/dsh-personal-agent/issues/31). [Packaged alpha evidence](PA-028.md) links the executable fixtures for the project brief, research, reminder, review, code change and document organization journeys.

## Paired native foreground and Worker pilot

Both arms receive the same synthetic inventory records, precedence rule and report format from the [organization fixture](PA-028.md#live-document-and-data-organization). The foreground arm submits one prompt to a native DSH Session. The Worker arm creates, starts and accepts one task through the authenticated Inbox. The probe reads the foreground Session's committed response and the Worker's sealed result. It applies the same exact CSV rubric to both and also checks the Worker artifact after a resident restart.

Both arms use the retained alpha archives, DSH 0.2.2-rc.1 and Node.js 24.14.1 on the same Linux host. A loopback meter checks the supplied task text, `deepseek-flash`, disabled thinking, zero model tools, at most one request per arm and a 256-output-token cap before forwarding to the official endpoint. The relay checks a 10,000 USD micro estimate ceiling per arm and records provider usage. The Worker also uses its native reservation and settlement path. The test checks the settled usage and estimate against the relay. Estimates use the same configured peak rates in both arms.

```sh
for order in foreground-first worker-first; do
  DSHPA_INSTALL_LIVE_DEEPSEEK=1 DSHPA_INSTALL_LIVE_ORGANIZATION=1 \
    DSHPA_INSTALL_PAIRED_ORGANIZATION=1 DSHPA_INSTALL_PAIR_ORDER="$order" \
    DSHPA_INSTALL_ARCHIVES="$archives" pnpm test:install
done
```

The test requires the authorized credential described in the [installation evidence](PA-028.md#live-deepseek-worker-smoke-test). Both orders and a final foreground-first repeat passed on 2026-11-16. All six results met the exact three-row rubric and exported CSV SHA-256 `5c5d9f82cabf8202bc7b48522462e2b3554814a43c2015a883508bccf2371d89`.

The first attempts exposed a missing preset insertion and inherited foreground tools. ## Paired research brief and code patch

Both workflows use the same archives, host and budgets as the organization pilot. The relay checks that both arms receive the same task text. The native foreground and Worker can supply different runtime instructions around that text. The Worker settles one provider call per pair and returns its accepted result unchanged after a resident restart.

- **Research brief.** The fixture reads two exact source revisions through the authenticated knowledge interface and checks that the earlier Harbor Room revision is rejected. Both arms receive the same selected excerpts. Each brief must cite the current revisions, give both capacities and fees, and recommend Harbor Room with a reason. The [research fixture](PA-028.md#live-research-brief-with-exact-local-sources) supplies the same rubric to both arms.
- **Code patch.** Each arm proposes a patch for the same synthetic zero-reading bug. The harness starts with two independent copies of the seeded Git repository, each with the same one failing test. It checks that each proposal changes only `readings.mjs`, applies it with Git and verifies all four cases in the isolated Node runner. See the [code fixture](PA-028.md#live-code-patch-with-executable-verification).

```sh
for workflow in RESEARCH CODE; do
  for order in foreground-first worker-first; do
    env DSHPA_INSTALL_LIVE_DEEPSEEK=1 "DSHPA_INSTALL_LIVE_$workflow=1" \
      DSHPA_INSTALL_PAIRED=1 DSHPA_INSTALL_PAIR_ORDER="$order" \
      DSHPA_INSTALL_ARCHIVES="$archives" pnpm test:install
  done
done
```

The first research foreground arm did not finish its provider turn normally. The first Worker-first code run returned a malformed patch. The revised prompts specify a three-line brief and the full-file diff hunk format. The rubric, model and budgets stayed the same. Both arm orders passed for each workflow on 2026-11-16. The existing organization flag and keyless installation also passed their regression runs. [Research and code verification #166](https://github.com/MosBot-AI/dsh-personal-agent/issues/166)

## Paired project brief clarification

The [project brief fixture](PA-028.md#live-project-brief-with-clarification) gives both arms the same fictional library pilot and withholds the audience and opening date. Each arm must ask for both missing facts. The harness restarts the resident before submitting the same scripted answer to each arm. It reads the original clarification from the same native foreground Session and the same inactive input wait from the Worker's Inbox task after restart.

The relay verifies two completed calls for each arm, with the original task text present on both calls and the exact owner answer present on the second. Both arms use the retained archives and the same `deepseek-flash` settings, with no model tools, thinking disabled, and caps of 256 output tokens and 10,000 estimated USD micros per call. All final briefs passed the same four-fact rubric. The accepted Worker artifact also matched on readback after a second Worker restart, and both settled usage records matched the relay.

## Paired inventory reviews

Both arms review the same three fictional inventory changes under the policy in the [installed review fixture](PA-028.md#live-reviews-and-reuse-of-a-reviewed-skill). The decision is to approve IR-21, return IR-26 for exceeding the unit limit, and return IR-42 for a missing supporting record. Each review must match the same exact three-line Markdown. The foreground takes all three prompts in one native Session, retaining earlier turns. The Worker uses three separate Inbox tasks. After each arm restarts the resident, the test reads all three results from the original Session or from the Worker's accepted artifacts.

The relay matches the source text for each call and checks the same `deepseek-flash` model, disabled thinking, zero model tools, and one call per request capped at 256 output tokens and 10,000 estimated USD micros. Both arms use the retained alpha archives and DSH 0.2.2-rc.1. The Worker settles all three calls and the test matches each settlement to its relay record.

Both orders passed on 2026-11-16. All twelve results met the exact rubric. Output usage was 41 tokens for IR-21, 39 for IR-26 and 38 for IR-42 in each arm.

## Paired reminder recovery

Both arms schedule the same fictional library delivery reminder, then change its text and push its due time back four seconds. The harness stops the resident before the first due time and waits until at least 500 ms after the revised due time to start it again. It verifies one delivery with the revised text and intended time, then reopens the same profile again and checks the same persisted delivery.

The foreground arm uses the pinned DSH scheduler with one ordinary native Session. It sends two successful owner commands, create and edit. The test binds the single reminder message in the Session to the exact native delivery receipt. The first probe counted schedule change notices as reminder messages. The test now classifies one-shot deliveries by their native reminder frame. The [installed Inbox path](PA-028.md#packaged-reminder-edit-and-cold-recovery) sends four successful owner commands, save, arm, edit and re-arm. The revised Inbox reminder matches its one SQLite occurrence receipt. Each arm rejects a stale edit or arm command.

```sh
for order in foreground-first worker-first; do
  DSHPA_INSTALL_REMINDER=1 DSHPA_INSTALL_PAIRED=1 DSHPA_INSTALL_PAIR_ORDER="$order" \
    DSHPA_INSTALL_ARCHIVES="$archives" pnpm test:install
done
```

Both arm orders passed on 2026-11-16 with the retained alpha archives, DSH 0.2.2-rc.1 and Node.js 24.14.1. Both arms use a keyless profile whose provider endpoint rejects requests on loopback. Native DSH attempted one provider request per run after admitting the reminder to the Session. The Inbox initiated zero provider requests, and its snapshots showed zero active Worker slots. Neither arm incurred an external provider charge.
