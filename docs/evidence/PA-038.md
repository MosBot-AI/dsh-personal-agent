## Implemented boundary

- `@mosbot-ai/dshpa-plugin-api` version `0.1.0` exposes exact capability API version `1`, typed definitions and provider contracts, strict scoped DTOs, configuration schemas, and lifecycle operations. Media, memory, retrieval and creation workflow share explicit destination and mock declarations.
- The native `dshpaPlugins` service exposes registration. The private core registry validates version and config before start, reports exact readiness, and selects an explicitly ready pin. A pin carries configured instance ID, implementation ID, plugin version and config revision. Disposal closes admission before waiting for accepted calls and late startup, then drains and stops once.
- Core consumers check trusted authority before handoff and recheck disclosure after asynchronous reads. Memory hits require an exact canonical record, revision and source match. Forgetting records the core exclusion before asking a provider to delete. Imported tombstones require confirmed exclusions, and stale active records remain excluded.
- Media submission validates modality, dimensions and approved artifact references. Inspect, cancel and collect use a recorded job and its original pin. Workflow child calls inherit the task scope and stay inside the current lifecycle. The trusted media intent and accepted-handle callbacks keep reconciliation evidence independent of workflow output.
- The testkit checks exact pin behavior and memory snapshot round trips. The local memory and clearly labeled mock media examples are separate packages loadable by DSH. The mock serves fixture metadata and lifecycle behavior.
