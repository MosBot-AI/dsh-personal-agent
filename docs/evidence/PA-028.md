# PA-028 packaged native Worker preflight

[简体中文](PA-028-zh.md) · [Documentation index](../README.md)

This check covers clean installation and native Worker dispatch for the alpha package. The release gate and its remaining acceptance are tracked in [PA-028](https://github.com/MosBot-AI/dsh-personal-agent/issues/32).

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test:install
```

The test packs the core bundle and its two workspace dependencies. The pinned DSH CLI initializes a fresh named Web profile and installs the core archive. The fixture preserves DSH's generated `nodeLinker: hoisted` and `autoInstallPeers: false`, and appends local archive references for the two workspace dependencies and permission to build Koffi. The installation resolves published dependencies from the package registry. DSH supplies the shared host packages at runtime. If a profile installs a second copy of `@deepseek-ai/dsh-llm`, its module-local request marks are different from the native Agent Loop's marks.

The installed bundle runs through the resident launcher. The test checks that the inbox requires authentication and that an owner can create and explicitly start a Worker. The pinned native provider sends exactly one request to a loopback endpoint that returns HTTP 400. The Worker releases into the expected provider wait, and the resident host shuts down cleanly. The run uses a synthetic credential and a local provider endpoint.

Main `917e84e` and the nine-PR integration tree `7d08796` passed the direct-install HTTP 400 control with matching result SHA-256 `baeeb36b4f99fee4cada60151f261699141e8be1ab7d627c542c8684f98ef479`. The installation settings and the separate credential recovery result are recorded in the release Issue. [Verification record](https://github.com/MosBot-AI/dsh-personal-agent/issues/32#issuecomment-6831354517)

## Plugin removal and reinstallation

The same packaged test stops the resident host and uses the pinned DSH CLI to remove dshpa from the disposable named profile. The installed bundle disappears. The separate WorkStore database, owner identity file and a file in the owner work directory retain their exact contents.

The test reinstalls the same archive in the existing profile and signs in through the new resident process. It reads the original task ID, version and resource wait. The worker stays inactive, and the controlled provider receives only the original POST across both process lifetimes. The test uses an isolated DSH home and a synthetic HTTP 400 provider. [Removal verification #144](https://github.com/MosBot-AI/dsh-personal-agent/issues/144)

## Packaged schema upgrade and restore

The historical source checkpoint `07579662e0747acdac1ad34f0f823c41e9ec8b0d` (schema 15) and current runtime `02ec24eec147a0277e19bf9bea2b83d34f1559b6` (schema 16) were built and packed separately. Both identify their unpublished core package as `0.0.0`. The test uses separate archives with the pinned DSH 0.2.2-rc.1 host and Node.js 24.14.1 on Debian 13. [Upgrade verification #146](https://github.com/MosBot-AI/dsh-personal-agent/issues/146)

The older installed bundle creates a project and starts a Worker through the authenticated native inbox. After one synthetic HTTP 400, the task waits for the provider. The pinned DSH CLI installs the current archive into the existing profile. The first new process upgrades the database to schema 16, retains the original project and task rows, and creates the owner-private `state.sqlite.v15.bak` with the pre-upgrade rows. The owner identity and work file are unchanged.

Restoring that backup to a fresh directory leaves the backup and upgraded database intact. The restored host returns HTTP 503 for readiness, lets the authenticated owner read the original task, and rejects dispatch with `recovery_required`. The provider receives one request total across the old, upgraded and restored hosts. SQLite integrity and foreign-key checks pass for all three databases and the backup.

From the current checkout, build both revisions and set `DSHPA_INSTALL_UPGRADE_FROM` to the built historical checkout:

```sh
previous="$(mktemp -d)"
git worktree add --detach "$previous" 07579662e0747acdac1ad34f0f823c41e9ec8b0d
pnpm -C "$previous" install --frozen-lockfile
pnpm -C "$previous" build
pnpm install --frozen-lockfile
pnpm build
DSHPA_INSTALL_UPGRADE_FROM="$previous" pnpm test:install
git worktree remove "$previous"
```

Both the upgrade case and the default installation case passed, along with 35 SQLite migration tests. The complete release gate still requires applicable verification on release artifacts, live-provider acceptance and the seven-day trial. See [Evaluation and release gates](../07-evaluation-and-release-gates.md).

## Local alpha archives

Build a clean checkout with the pinned workspace toolchain, then retain the three archives outside the disposable installation profile. These are local artifacts for verification. [Archive verification #148](https://github.com/MosBot-AI/dsh-personal-agent/issues/148)

```sh
pnpm install --frozen-lockfile
pnpm build
archives="$(mktemp -d)"
for package in personal-agent plugin-api model-routing; do
  pnpm -C "packages/$package" pack --pack-destination "$archives"
done
cp LICENSE "$archives/LICENSE"
git rev-parse HEAD > "$archives/source-commit.txt"
(cd "$archives" && sha256sum ./*.tgz LICENSE > SHA256SUMS && sha256sum -c SHA256SUMS)
DSHPA_INSTALL_ARCHIVES="$archives" pnpm test:install
```

`DSHPA_INSTALL_ARCHIVES` uses the exact three files at an absolute path and runs the authenticated startup, removal and reinstallation checks. Omit `DSHPA_INSTALL_UPGRADE_FROM` for this run. The pinned source `b94773c1b0370335e3a3b8031d212673b54702a5` was packed with Node.js 24.14.1, pnpm 11.28.5 and DSH 0.2.2-rc.1. All three archives contain the Apache-2.0 license, and the core and routing package manifests resolve their workspace references to concrete versions. The archived files passed the local native test with a synthetic provider. The live-provider and alpha trial gates remain open.
