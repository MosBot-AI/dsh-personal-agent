# PA-028 packaged native Worker preflight

[简体中文](PA-028-zh.md) · [Documentation index](../README.md)

This check covers clean installation and native Worker dispatch for the alpha package. The release gate and its remaining acceptance are tracked in [PA-028](https://github.com/MosBot-AI/dsh-personal-agent/issues/32).

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test:install
```

The test packs the core bundle and its two workspace dependencies. The pinned DSH CLI initializes a fresh named Web profile and installs the core archive. The fixture preserves DSH's generated `nodeLinker: hoisted` and `autoInstallPeers: false`, and appends local archive references for the two workspace dependencies and permission to build Koffi. The installation resolves published dependencies from the package registry. DSH supplies the shared host packages at runtime. If a profile installs a second copy of `@deepseek-ai/dsh-llm`, its module-local request marks are different from the native Agent Loop's marks.

The installed bundle runs through the resident launcher. The test checks that the inbox requires authentication and that an owner can create and explicitly start a Worker. The pinned native provider sends exactly one request to a loopback endpoint that returns HTTP 400. The Worker releases into the expected provider wait, and the resident host shuts down cleanly. The run uses a synthetic credential and a local provider endpoint.

Main `917e84e` and the nine-PR integration tree `7d08796` passed the direct-install HTTP 400 control with matching result SHA-256 `baeeb36b4f99fee4cada60151f261699141e8be1ab7d627c542c8684f98ef479`. The installation settings and the separate credential recovery result are recorded in the release Issue. [Verification record](https://github.com/MosBot-AI/dsh-personal-agent/issues/32#issuecomment-6831354517)

## Plugin removal and reinstallation

The same packaged test stops the resident host and uses the pinned DSH CLI to remove dshpa from the disposable named profile. The installed bundle disappears. The separate WorkStore database, owner identity file and a file in the owner work directory retain their exact contents.

The test reinstalls the same archive in the existing profile and signs in through the new resident process. It reads the original task ID, version and resource wait. The worker stays inactive, and the controlled provider receives only the original POST across both process lifetimes. The test uses an isolated DSH home and a synthetic HTTP 400 provider. [Removal verification #144](https://github.com/MosBot-AI/dsh-personal-agent/issues/144)

The complete release gate still requires upgrade and migration evidence, release restore validation, live-provider acceptance and the seven-day trial. See [Evaluation and release gates](../07-evaluation-and-release-gates.md).
