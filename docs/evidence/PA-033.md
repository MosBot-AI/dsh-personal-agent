## Implemented

- The opt-in resident service queues scoped image and video jobs in SQLite v14. It selects a configured local, free provider by modality, pins its configuration, checks the current attempt and caps the queue and per-attempt submissions. One media lease survives cold opens. A rate-limited preparation waits before rejoining the eligible FIFO. This loop runs separately from Worker slots.
- The ComfyUI 0.44.0 adapter accepts approved API graphs with installed models and probes the local server, CPU or GPU and output filesystem. Before the request leaves the process, SQLite commits the client-assigned prompt ID, request and workflow digests, seed and exact provider pin. Ambiguous submissions enter readback with the same handle. A missing queue and history record leaves the outcome uncertain and the lease held.
- The adapter verifies an ownership binding before using ComfyUI's per-job cancellation route. It downloads bounded output from approved output nodes, probes the media type, dimensions and duration, decodes the stream and computes SHA-256. The job stores verified metadata. ComfyUI retains the output files. [Provider setup](../../packages/media-comfyui/README.md)
## Media regression setup

The media regressions use a loopback HTTP test double shaped for ComfyUI v0.44.0. ComfyUI is absent from this test environment. FFmpeg generates the PNG and MP4 samples served by the test double. The reported SHA-256 values are hashes of these samples.

- In the [requested dropped-response case](https://github.com/MosBot-AI/dsh-personal-agent/issues/33#issuecomment-6715554235), the test double records one POST, enqueues a simulated job and closes the socket before replying. A separate SQLite connection sees the prepared record at the moment of submission. The caller reopens the store and registry, sees an empty readback, then reconciles the same simulated prompt ID and verifies the fixture PNG digest. The final POST count stays at one.
- In the process-crash case, the test double records the submission and withholds the reply. The test sends `SIGKILL` to its disposable dshpa caller process. SQLite still shows `submitting` and the prepared prompt ID. A second process opens that database, reconciles the simulated job and verifies the FFmpeg sample hash. The test double records exactly one POST.

E16 has FFmpeg-generated and decoded samples, scoped cancellation against the test double and a simulated backend OOM status. E18 has the native resident host smoke suite and a separate media caller reopen. E21 has a separately built provider and configuration-pinned readback.

Live ComfyUI image and video rendering, actual GPU availability and OOM, running-job cancellation on the physical host, and media recovery through real sleep and wake remain pending.
