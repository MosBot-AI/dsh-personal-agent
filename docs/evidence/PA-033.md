# PA-033 durable local media evidence

[简体中文](PA-033-zh.md)

[PA-033](https://github.com/MosBot-AI/dsh-personal-agent/issues/33) · Plan `2026-11-07-r7` · Initial implementation `740fe3436008fa07e1a5ab0e12864db010484dfb`. The integrated schema-16 behavior is recorded below.

## Implemented

- The opt-in resident service queues scoped image and video jobs in SQLite v16. It selects a configured local, free provider by modality, pins its configuration, checks the current attempt and caps the queue and per-attempt submissions. One media lease survives cold opens. A rate-limited preparation waits before rejoining the eligible FIFO. This loop runs separately from Worker slots.
- The ComfyUI 0.44.0 adapter accepts approved API graphs with installed models and probes the local server, CPU or GPU and output filesystem. Before the request leaves the process, SQLite commits the client-assigned prompt ID, request and workflow digests, seed and exact provider pin. Ambiguous submissions enter readback with the same handle. A missing queue and history record leaves the outcome uncertain and the lease held.
- The adapter verifies an ownership binding before using ComfyUI's per-job cancellation route. It downloads bounded output from approved output nodes, probes the media type, dimensions and duration, decodes the stream and computes SHA-256. The job stores verified metadata. ComfyUI retains the output files. [Provider setup](../../packages/media-comfyui/README.md)
## Media regression setup

The earlier media regressions used a loopback HTTP test double shaped for ComfyUI v0.44.0. ComfyUI was absent from that test environment. FFmpeg generates the PNG and MP4 samples served by the test double. The reported SHA-256 values are hashes of these samples.

- In the [requested dropped-response case](https://github.com/MosBot-AI/dsh-personal-agent/issues/33#issuecomment-6715554235), the test double records one POST, enqueues a simulated job and closes the socket before replying. A separate SQLite connection sees the prepared record at the moment of submission. The caller reopens the store and registry, sees an empty readback, then reconciles the same simulated prompt ID and verifies the fixture PNG digest. The final POST count stays at one.
- In the process-crash case, the test double records the submission and withholds the reply. The test sends `SIGKILL` to its disposable dshpa caller process. SQLite still shows `submitting` and the prepared prompt ID. A second process opens that database, reconciles the simulated job and verifies the FFmpeg sample hash. The test double records exactly one POST.

## Recovery from verifier temporary storage exhaustion

A loopback HTTP fixture serves a valid FFmpeg-generated PNG for an already completed prompt. The test injects `ENOSPC` and `EDQUOT` separately when the verifier creates its private directory and writes its input file. On the prior implementation all four cases failed with `invalid_result`. The adapter now reports `busy`. The job stays in `collecting` and retains the lease through a cold WorkStore reopen. With storage available, FFmpeg decodes the PNG and the stored SHA-256 matches the fixture. Each case submits exactly one prompt.

The file-write cases also cover cleanup of a partial file and preservation of the original capacity error if cleanup reports an error. A separate check cancels during cleanup and confirms that the provider reports `cancelled`. The existing corrupt-output test still reports `invalid_result`. These checks use fault injection and the loopback provider fixture. [Recovery #123](https://github.com/MosBot-AI/dsh-personal-agent/issues/123)
