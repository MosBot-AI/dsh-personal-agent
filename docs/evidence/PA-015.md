## Implemented boundary

- The local Web inbox accepts only explicitly configured, read-only knowledge roots. Each root has include and exclude patterns, a type allowlist and file, byte and traversal budgets. Unavailable roots stay visible by configured ID while other roots remain usable.
- Descriptor-relative traversal checks each component with `openat` and `O_NOFOLLOW`. Enumeration and reading use read-only descriptors. Hidden entries, hard links, nonregular files, unsupported content and oversized files are skipped. The inbox projects relative paths, stable IDs and SHA-256 content revisions.
- The derived in-memory index reuses unchanged entries, removes deleted or unreadable entries and rechecks the current source before returning a match. Chinese and mixed-language keyword search uses Unicode normalization. Exact pages validate the reference, revision, access and UTF-8 byte boundary.
- The authenticated owner uses the Local knowledge panel to inspect root status, search and open bounded pages. It displays document text as data. Source text stays separate from Worker input, personal memory and native compaction summaries.

## Keyword ranking verification (2026-11-12)

Local keyword search prioritizes a normalized exact relative path or filename. For other eligible matches it ranks distinct query terms found in document text, then up to three occurrences per term, followed by the previous score and path tie-breaker. The opening Markdown title still contributes to eligibility and the previous score. The index stores an offset in the existing normalized text for body scoring. Source permission checks, exact revision reads and proactive rule matching keep their original semantics. [Ranking issue](https://github.com/MosBot-AI/dsh-personal-agent/issues/90)

The controlled Linux run used pinned native DSH Web 0.2.2-rc.1 and Node.js 24.14.1 with authenticated search and exact source readback. The baseline was dshpa `917e84efaf26c00f7a62b3b02c6253be72e8b8ed`. Both synthetic corpora and their expected sources were frozen before testing the change. A sourced hit requires the annotated path within the measured rank and a successful read of its exact revision and answer span.

| Frozen sample | Sourced keyword hit@1, baseline → candidate | Sourced keyword hit@3 |
| --- | --- | --- |
| Original, 42 documents and 30 keyword queries | 19/30 → 27/30 (90.0%). English 6/10 → 9/10, Chinese 7/10 → 8/10, mixed 6/10 → 10/10. | 30/30 in both runs. |
| Independent holdout, 60 documents and 36 keyword queries | 12/36 → 36/36. Each language group moved from 4/12 to 12/12. | 36/36 in both runs. |

On the original set, the three remaining keyword misses (`en-03`, `zh-13`, `zh-19`) still returned the annotated source at rank 2. All 30 exploratory natural-language formulations returned no results in both runs. Across both candidate runs, all 138 returned sources matched their exact bytes and revisions, and all 12 no-answer controls stayed empty. All 18 exact filename or relative-path holdout queries returned the expected source first. No previously correct first result regressed on either set. The holdout intentionally stresses filename-heavy distractors. These measurements cover controlled keyword queries and file navigation.

## Natural-question retrieval

[Issue #129](https://github.com/MosBot-AI/dsh-personal-agent/issues/129) adds a local search fallback for questions after strict lookup finds no current results. It segments a bounded number of query terms, weights matches by frequency across the selected roots, and requires related terms in a body passage. It can omit weak or closely ranked candidates. Source scope, revision validation, exact filenames and the proactive rule matcher keep their existing behavior. Results are document candidates and can miss paraphrases that share few words with a source.

The native Web benchmark uses synthetic, frozen corpora and exact authenticated source readback. The baseline is `bec8456`. The candidate was tested on Debian 13 with DSH `0.2.2-rc.1`, Node.js `24.14.1` and ICU `78.2`. The runner records miss IDs, invalid queries, no-answer controls, and sourced hit@1 and hit@3 by language and mode.

| Original natural questions | 0/30 · 0/30 | 9/30 · 9/30 | 7/10 · 1/10 · 1/10 |
| Keyword and navigation holdout | 54/54 · 54/54 | 54/54 · 54/54 | 18/18 · 18/18 · 18/18 |

All 220 candidate source readbacks matched their exact reference, revision and document bytes. All 30 no-answer controls returned no results. The baseline rejected 12 positive questions under its whitespace-term limit across the two natural-language holdouts. The candidate admitted all 90. The holdouts were authored independently and frozen before scoring. Early candidates returned results on two of nine no-answer controls in the first holdout and four of nine in the second. Those misses informed the final evidence rules, so the final scores are measured against frozen regression sets and need a fresh holdout to estimate generalization.

The original 60-query sample reached 36/60 sourced hit@1 (60%) and 39/60 hit@3 (65%). These are 20 and 15 percentage points below the plan's 80% target, respectively. Twenty-one of the original natural questions still missed at rank one, including nine in Chinese and nine in mixed language. ## Offline multilingual retrieval comparison

[Issue #131](https://github.com/MosBot-AI/dsh-personal-agent/issues/131) compared the shipped lexical search at `9714da4` with a CPU-only multilingual E5 encoder and weighted reciprocal-rank fusion. The benchmark used an independent 63-question synthetic holdout and 15 no-answer controls, with 21 answerable questions and five controls each for English, Chinese and mixed language. The 42 documents include 21 annotated sources and 21 similar-topic distractors. The 24-question calibration corpus and its 24 controls use distinct documents. The holdout was frozen before calibration and first scored after fixing cosine cutoff 0.92, minimum leading gap 0.03 and lexical weight 0.75. Exact path and filename results take priority in the hybrid. [Model card](https://huggingface.co/intfloat/multilingual-e5-small/blob/614241f622f53c4eeff9890bdc4f31cfecc418b3/README.md)

| Held-out method | Sourced hit@1 | Sourced hit@3 | No-answer queries with results |
| --- | --- | --- | --- |
| Native lexical | 44/63 | 44/63 | 5/15 |
| Calibrated dense | 2/63 | 2/63 | 1/15 |
| Calibrated hybrid | 44/63 | 44/63 | 6/15 |
| Dense without abstention, diagnostic | 47/63 | 61/63 | 15/15 |

The hybrid matched the same first-rank answers as lexical. Per-language hit@1 was 18/21 English, 13/21 Chinese and 13/21 mixed for both methods. The dense policy matched two Chinese direct questions. Lexical and hybrid matched 20/21 direct, 11/21 paraphrase and 13/21 contextual questions. All 42 document sources and 63 answer anchors were read back through authenticated native Web with exact reference, revision and bytes. Rankings reproduced across ten fresh native hosts and ten fresh dense processes. The [machine-readable results](../../evals/retrieval/results.json) include miss IDs, per-language and mode counts, regression scores and report digests.

On Linux x86-64 with Ryzen 9 5900HX, Node.js 24.14.1, DSH 0.2.2-rc.1, Python 3.13.5 and four ONNX Runtime inference threads, native warm search p95 was 7.16 ms over 1,000 RPCs, including native RPC overhead. A dense run's 100 timed queries had warm p95 8.34 ms. The paired sequential estimate for native search plus dense scoring and fusion was 13.34 ms p95 on the initial run. The hybrid was an offline composition. Across ten fresh processes with filesystem caches retained, first index plus search p95 was 43.20 ms for the native host, with host startup measured separately at 2,030 ms p95. Dense model load, indexing and first search together reached 1,566 ms p95, excluding the asset hash check. Peak RSS was 361,944 KiB for the native host and 1,195,980 KiB for dense. With ten samples the nearest-rank p95 is the observed maximum.

The tested hybrid did not improve first-rank recall on the independent holdout and returned one extra no-answer result. The original 60-query regression improved from 36/60 to 38/60 first-rank hits with hybrid, below the 80% plan target. The measurements support keeping the current lexical product behavior. A future evaluation can compare stronger retrieval and an answerability check on a fresh corpus. The broader alpha acceptance remains on [Issue #32](https://github.com/MosBot-AI/dsh-personal-agent/issues/32). [Reproduction steps](../../evals/retrieval/README.md)
