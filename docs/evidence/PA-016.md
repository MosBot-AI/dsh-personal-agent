## Implemented boundary

- The local owner authorizes one exact GitHub account and repository, optionally bound to one active dshpa project. REST reads verify numeric IDs and current names before each page. The connector uses fixed authenticated GET endpoints, bounded JSON, and opaque process-local cursors tied to the exact operation and issue.
- The registry applies local concurrency and rate limits and honors GitHub backoff. It rejects cross-account, cross-repository and cross-project data before disclosure. Source text stays outside Worker input, routing intake and action authority. [GitHub REST rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)
- A reviewed loopback MCP facade can supply the same read DTOs. The bridge compares the configured fingerprint against discovery before and after invocation. It uses three exact tool names, bounded JSON or SSE responses, and sends no GitHub token to MCP. The facade owns its provider-side read permissions. [MCP transports](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports) · [MCP tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)
- The authenticated Web panel verifies connection status and reads issue and comment pages. It renders provider text literally and generates links only for the configured repository.
