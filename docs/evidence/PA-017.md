## Implemented boundary

- An explicitly configured test repository, active dshpa project, GitHub identity and base ref define the only route. The owner prepares one Markdown file in a temporary bare Git workspace. The approval preview binds the repository, base and head refs and commits, title, marked body, file content and SHA-256 digests.
- The WorkStore records the exact effect and approval together. Publication uses a one-use claim and a Git lease for a new head only. The connector revalidates the grant between branch publication and the draft PR call. It also checks the live base and head before the fixed draft endpoint.
- Read-only reconciliation checks the provider account, repository, refs, commit IDs, title and body against the immutable marker. A unique exact result becomes a provider receipt and a sealed task artifact. No match or an ambiguous result remains uncertain. The connector has no automatic replay or remote cleanup.
- The normal local Web carrier exposes explicit preparation, approval, publication, revocation and lookup. The feature requires the separate `DSHPA_GITHUB_WRITE_TOKEN` for the configured test repository. [GitHub draft PR API](https://docs.github.com/en/rest/pulls/pulls?apiVersion=2022-11-28#create-a-pull-request)
