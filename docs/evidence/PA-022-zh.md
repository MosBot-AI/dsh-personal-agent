## 设备与回放

- WorkStore 生成与所有者和资料范围绑定的五分钟一次性配对码。注册成功时，以独立的三十天凭据摘要原子替换配对码摘要。数据库保存摘要和设备元数据。撤销或过期后，下次检查就会移除设备权限。备份恢复会清除恢复副本中的旧待配对和已注册凭据。
- 独立于传输层的事件源对每次快照和回放进行鉴权。它读取现有 WorkStore 中关联会话的任务，在范围内的游标后回放最多 128 条已提交事件。游标缺失、超出范围或过期时要求获取新快照。事件包含任务 ID、版本、状态和时间。快照省略会话标识、来源目的地、私有约束及产物。
- 固定版本的 DSH Web 连接将浏览器凭据映射为共享的 owner Peer。精确 Fetch 路由要求这个 owner Peer。现有收件箱还会将审批绑定到精确的客户端、设备和会话。这些边界决定了独立的移动设备接入路径和显式审批移交。 [固定宿主证据](host-compatibility-zh.md) · [原生访问契约](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/api/remote-access/README.md)

## 移动 HTTP 与 Web

提交 `d833b4a21a49c56641ae1cda2a021d87b4cd76b6` 将账本与事件源接入可选的回环 HTTP 监听。独立 HTTPS 源地址由操作者的反向代理终止 TLS。上游校验 Host、Origin 和 Fetch Metadata，配对设置独立的 Secure、HttpOnly、SameSite=Strict Cookie。原生本机所有者通过待办面板生成配对码并撤销设备。

独立的响应式页面读取限定范围的快照并订阅 SSE。超出窗口的游标会要求获取新快照。事件流每次轮询都重新核验设备，设备撤销后关闭。移动监听提供自身的静态资源、配对、快照、事件及已分配审批路由。 [配置方法](../../README-zh.md#启用移动任务视图)

## 移动精确审批

提交 `9373a93dd183b9a1ecba14adc816e4134b3845dc` 加入向单个已注册设备移交审批的版本约束，以及由原所有者客户端撤回审批的能力。WorkStore v15 分别保存原始审批绑定与被分配的答复方。手机将预期版本、摘要及批准或拒绝的决定提交给现有精确动作门禁。门禁核对移动授权的设备注册状态，协调器仍对原动作最多领取一次。SSE 审批提示省略预览。已认证页面通过独立请求读取精确审批卡片，并提供 Web 应用清单。

## 移动审批答复恢复

[维护工单 #92](https://github.com/MosBot-AI/dsh-personal-agent/issues/92) 涵盖在主分支 `917e84e` 上复现的两个问题。审批 POST 未收到答复时，即使重新读取审批，操作按钮也会一直禁用。已失效配对的请求迟到返回 HTTP 401 时，也可能清除新会话的界面。

实现提交 `29b194a` 将每次提交限制为十秒。结果无法确认时，页面重新鉴权读取任务快照与审批列表，且不会自动重发 POST。事件流重连或游标重置时，当前界面保留正在提交的审批。会话结束、页面隐藏或离开时，原有待处理答复失效。每个答复仅在自身请求仍有效时更新界面，即使同一审批 ID 已发起了新请求也一样。服务端继续校验已登记设备、精确的审批版本与摘要，以及一次性授权。

在 Debian 13、Node.js 24.14.1、DSH 0.2.2-rc.1 和 Chromium 154 上，本地类型检查、工作区构建、333 项无凭据测试、5 项原生移动端测试和 12 项协调测试均通过。4 项确定性审批用例在修复版本上通过，其中 2 项在主分支复现了缺陷，另 2 项用于确认已有行为，原本就通过。与 #83 及待合并共享 API 分支的集成预览通过了 7 项审批与刷新用例。另一次使用受信任本地 TLS 的原生 DSH 与 Chromium 验证中，唯一一个挂起的 POST 被取消，重新读取后两个按钮在 10.08 秒恢复。原审批仍为待处理，浏览器只发出一次 POST。外部 HTTPS 部署和实体设备验收仍待完成。

## 慢速连接和重连后的刷新

[Issue #82](https://github.com/MosBot-AI/dsh-personal-agent/issues/82) 在实际交付的移动端脚本中复现了两种页面数据过期的情况。快照和审批请求耗时 1,250 毫秒时，每秒到达的任务事件曾反复取消进行中的刷新。重连成功后，已触发的重试定时器曾阻止新事件流安排刷新。

现在，进行中的刷新会先完成，期间到达的任务和审批事件合并为一次后续刷新。刷新超过 10 秒未完成时进入重连流程。重连回调先释放定时器，再请求快照。页面隐藏、会话失效和游标重置时，仍会取消进行中的请求并清除已渲染的任务和审批。使用确定性时钟的 DOM 测试在原脚本上复现了两处故障，并验证了修复后的后续刷新、请求卡住后的恢复、隐藏时清除内容，以及忽略已关闭事件流的回调。

已部署 HTTPS 和实体手机仍待验收。
