## Implemented boundary

- `openWorkStore(directory)` owns one SQLite connection in a private application directory. A separate persistent guard database holds an exclusive transaction for the lifetime of the store. Process exit releases that lock. The work database uses WAL, full synchronization, and foreign keys. POSIX file and directory permissions are checked, including SQLite sidecars.
- One synchronous transaction checks command and source deduplication, applies the task version and attempt generation fences, and commits the task, attempt, scoped work event, prepared effects, pending deliveries, and command receipt. Foreign keys bind effect and delivery intents to the exact attempt generation. Cancellation can advance the task generation while retaining the retired attempt for reconciliation.
- Command replay uses the authenticated owner and client key and a fingerprint of the canonical request and trusted routing scope. An exact replay returns the prior receipt before checking the current task version. Changed requests conflict, and records decoded from storage must match their enclosing scope. Each transaction accepts up to 64 effect and delivery intents and 1 MiB of encoded records.
- Migration 001 initializes an empty database and commits the application identifier and schema version with the tables. Unsupported versions and foreign databases are refused in place. Corruption creates an on-disk quarantine marker, closes the connection, and prevents normal reopen or empty replacement. The database remains at its original path. Normal SQLite close can checkpoint the WAL.

| Scenario | Verified PA-004 behavior | Later product work |
| --- | --- | --- |
| E03 | Exact command replay survives reopen. Changed commands and changed trusted routes conflict, repeated external revisions deduplicate, and wrong scope or stale versions reject writes. | Routing of actual source events and ambiguous follow-ups belongs to PA-010 and PA-014. |
| E06 | Work records, source links, effect and outbox intents, and receipts commit or roll back together. Reopen retains only committed rows after abrupt exit. Stale attempts cannot prepare new effects. | Provider dispatch, uncertain outcome reconciliation, and delivery are verified by the corresponding execution and recovery tasks. |
| E11 | Real SQLite capacity exhaustion rolls back initial schema creation and data writes. Unsupported files remain in place.
