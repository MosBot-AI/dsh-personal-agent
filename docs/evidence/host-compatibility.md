# PA-002 pinned DSH host compatibility

[简体中文](host-compatibility-zh.md)

The contracts run the published `@deepseek-ai/dsh@0.2.2-rc.1` CLI in temporary named profiles with local scripted model adapters. See [PA-002 evidence](PA-002.md) for commands and acceptance scope.

## Agent lifecycle and settlement

- `ctx.dshpa.host.agents.create()` and `resume()` use the native registry through the bundle's Cordis context. Callers receive native handles and can dispose an individual handle. Unloading the bundle aborted an active resumed agent with `{ kind: 'disposed' }` and removed its Agent and Session registrations.
- Idle `inject()` appended context without starting a turn. `followup()` started inference, while `steer()` and `inject()` during the blocked tool-call stream reached the next model request in the same turn. `cancel()` signaled the active stream and the turn settled as aborted. `whenIdle()` indicated runtime quiescence. Business completion still requires an application outcome and its evidence.
- The live `agent/assistant-stream` frames arrived in start, indexed chunks, and end order. The committed end referenced the sequence of the final `assistant/message`, whose compact stream expanded to the observed chunks. With partially delivered text in the cancellation fixture, the host persisted an interrupted `assistant/message` and an aborted `turn/end`. Use durable settlement events for replay and the process-local frames for presentation.

Use the native handles in PA-006 and native settlement as input to PA-007. The in-process cancel path does not establish cooperative cancellation by every external tool, rollback of side effects, or foreground fairness across jobs.

## Tool policy and persistence

- A scoped `tools.guard()` denied a tool after a permissive pre-execute hook. The native pipeline persisted an error tool result with the guard's reason, and the tool body was never called. The resumed agent could run the tool after the original scope was gone. The guard takes an immutable view of the execution and synchronously returns a denial reason or `undefined`. PA-005 owns the durable approval, grant, and revocation workflow.
- `ctx.dshpa.host.flush(session)` requires the native Session service and rejects if the native flush reports no participating listener. It preserves listener failures. With JSONL composed, the test read back the event sequence before disposing the agent and recovered it in a fresh DSH process. Compose the real persistence backend before relying on this barrier. Listener participation alone cannot establish that a particular backend wrote data.
- Session persistence owns the native transcript. The storage-domain document-row API has no transaction spanning Task, Approval, Effect, and Outbox records. PA-004 owns that atomic boundary in application SQLite. [Storage-domain contract](https://github.com/deepseek-ai/deepseek-harness/blob/66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db/packages/storage/storage-domain/README.md)

## Schedule delivery

The normal contract holds the Session flush barrier after the scheduled reminder enters the inbox. The test reads the message back through the native JSONL backend while the schedule is still active and has no receipt or assistant final. Releasing the barrier records a receipt for that message and ends the one-shot schedule. An immediate Run Now request reports `schedule_execution_pending`. A fresh process retains the single message and receipt.

The fault contract exits the DSH process with code 86 after the native backend exposes the stored inbox message and before the scheduler finishes the flush barrier. On restart, the same named Profile and a registered `schedule/resolve-agent` resolver allow native overdue delivery to replay the same schedule ID and occurrence timestamp. The log now contains two different message IDs, and the single saved receipt identifies the second one.

Reuse native schedule timing and receipt inspection in PA-018. Key application intake on the logical occurrence identity so a replay cannot dispatch another effect. A native delivery receipt establishes inbox admission. Business completion and arbitrary external effects need their own evidence. [Native schedule contract](https://github.com/deepseek-ai/deepseek-harness/blob/66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db/packages/schedule/schedule/README.md)

## Remote access controls

The installed `@deepseek-ai/dsh@0.2.2-rc.1` base bundle composes Typert Gateway and Remote Access. The Web app bundle adds the Connection carrier and the Session and Workspace controllers. The release source at `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db` matches the audited source at `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159` for `packages/api/gateway`, `packages/api/remote-access`, and `packages/api/workspace-controller`. The audited checkout also allows eligible empty continuation and recognizes first insertion after the inbox item was removed. The installed forwarding allowlist also omits the audited checkout's `web/providers-changed`. dshpa keeps command and effect idempotency in its own durable state. Two local probes ran with `env -i PATH="$PATH" node --input-type=module`, resolving published modules through `node_modules/.pnpm/node_modules`. Both exited 0. The first mounted the installed `@deepseek-ai/dsh-typert-registry`, `@deepseek-ai/dsh-api-remote-access`, and `@deepseek-ai/dsh-api-gateway` under Cordis. It invoked a fixture Remote method with a `Peer` from `@deepseek-ai/dsh-client-connection` and two Session resources. The owner passed. A missing policy, a global-only grant, a missing second grant, an empty resource list, and policy disposal each denied the call before the method ran. Both Session grants admitted the non-owner.

The second probe registered `TYPERT` from installed `@deepseek-ai/dsh-api-remote-access/typert` (`lib/typert.host.js`). An in-process `remoteAccess/follow` yielded a binding for a custom `task` kind. The published `remoteAccess/follow` result codec rejected that frame via `descriptor.result.create().safeParse(frame)`. The codec enumerates `global`, `session`, and `workspace`. PA-022 must verify the compiled client path for any new Task, Artifact, or desktop resource kinds before relying on that snapshot. The probes used in-process dispatch and direct codec validation. Browser, network carrier, and live device authentication checks remain PA-022 work.

Reuse the native Gateway and Remote Access policy where they cover the declared resource and action. dshpa still owns trusted intake, task and artifact authorization, exact-action approvals, and revocation of in-flight product work. New resources need explicit readers and verification at their delivery boundaries.
