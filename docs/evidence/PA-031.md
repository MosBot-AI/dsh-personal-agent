## Implemented boundary

- In Today, the authenticated owner authorizes a task attempt for an exact macOS application or configured browser target. An OS-backed per-user reservation serializes desktop workflows across local profiles. The browser path binds its profile lease to a freshly isolated, exact native tab. Each model action rechecks the current lease and native target. Starting or continuing requires foreground authorization.
- The macOS path uses DSH Computer Use. It probes the session and Accessibility before model admission, then uses the provider's application consent and AX snapshots. The browser path uses DSH's Session-owned MCP runtime with pinned headless Chrome DevTools. The provider applies a configured network allowlist, and the task narrows tool calls to its own origin and tab. Structured page IDs route actions, and a bounded top-level observation supplies the only accepted element IDs.
- Takeover fences new input immediately and preserves the running operation's drain status. The Worker parks and releases its compute slot after teardown. Continuation creates a fresh lease and requires fresh observation. Browser Session teardown discards the isolated context.
- The dedicated deployment admits only its lease-gated model tool. Native shell and program execution stay disabled at this boundary. OS-level sandboxing requires a separately enforced backend.

## Independent review and owner-directed fixes (2026-11-09)

The independently reviewed PR #66 head was `4fbcedd7f57cf54733d66ab027311e7ae454d0c6`. Its existing `pnpm check` passed 263 tests, and its native host, resident and real-browser command passed 14 tests. A new two-origin case nevertheless reproduced an unauthorized disclosure: both sites were deployment targets, but the task was authorized only for A; B received `GET /frame` and a `POST /click` carrying the public fixture value `PA031 verified browser value`. The task still entered `verifying`. The failing request-count and body-capture runs are retained as review evidence. No real account or private user data was involved.

The owner then explicitly handed the fixes to this run. The candidate integrates main `c3c613391be888fffd3885fd955fadc30e337912`, resolving eight conflict files while retaining mobile approval, media schema v16 and the newer model-routing/compute boundaries. There is no new database migration. Original source files for the main storage schema, media jobs and mobile approval implementation were checked unchanged.

The browser provider now binds the exact Agent activation to the owner-approved origin and lease during private Worker setup, before the MCP process or browser opens. Each MCP process receives one task origin, rather than the deployment-wide origin list. The pinned `mountSessionMcp` helper accepts a single fixed argument array and cannot select task-specific launch authority. The adapter therefore reuses DSH `SessionResources`, `createScope`, browser registration and `McpClient` directly. DSH still owns MCP transport, tool definitions and Session serialization; no separate browser driver was implemented. Lease loss or takeover closes the MCP scope, and host startup failure awaits desktop drain before closing storage. Missing binding/provider availability parks work before task input reaches a model.

The real-browser regression exercises both configured sites as authorized task targets. Both can save their own value, while cross-profile frames, POSTs, popups and redirects receive no requests. The existing globally excluded-origin, profile contention and takeover case remains. The native Web fixture also checks an unavailable browser provider and verifies `worker_inputs.status = not_delivered`. CI now runs the two browser cases with an explicit Chrome executable in addition to the mobile/media/resident suites.
