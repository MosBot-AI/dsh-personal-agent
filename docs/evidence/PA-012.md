## Implemented boundary

- Authenticated owners can explicitly remember, search, inspect, correct and forget through the local Web inbox. Each operation uses exactly one profile, project or task scope. The view shows source receipts, revisions, confidence and validity, with separate projections for confirmed and inferred records. Automatic extraction is off, and the external knowledge base remains read-only.
- The independent SQLite memory provider stores fact values. It implements normalized search, revision checks, atomic supersession, tombstones and version-1 snapshot import and export. A failed import leaves the target scope unchanged.
- The schema-009 WorkStore ledger holds source receipts, revisions, state, digests and replayable command receipts. Correction or forgetting hides the old record before the provider call. Core completion requires exact readback from the pinned provider. A different preimage at the same revision leaves the operation pending. The same authenticated command and payload can retry a pending change.
- Reads recheck scope, authority, provenance and current ledger state. A stale provider copy cannot publish superseded or forgotten content, even when its read began before the exclusion. Explicit personal memory stays outside automatic Worker context and native compaction summaries.
