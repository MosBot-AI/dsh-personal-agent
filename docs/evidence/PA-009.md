## Implemented boundary

- A Worker launch or redirect commits the exact Attempt, generation, stable native message identity, cursor, rendered payload and digest in one SQLite transaction. Native input is eligible for inference only after the Session flush and matching SQLite acknowledgment. The journal retains the flush timestamp through later observations.
- Cold DSH readback checks the unseeded Session header, directory, stable revision, exact message ID and digest, and paged inbox events. It distinguishes pending, admitted, cancelled, absent, and ambiguous input. A claimed input without a committed user message remains unknown. Older records without equivalent evidence remain subject to reconciliation.
- Startup gates new native inputs, action claims, and Outbox sends while interrupted work is classified. Unproven cold Workers are fenced by generation and retain their wait reference where applicable. Existing confirmed release can settle an exact cancellation. New work can proceed after startup classification, while fenced attempts and uncertain deliveries retain their own restrictions.
- Cancellation persists the generation advance before signaling owned native work. Stale reports, new input intents, and acknowledgments cannot cross the retired generation. Exact cancellation considers unresolved effects and Outbox claims before final settlement.
- Effect and Outbox recovery preserve the original claim and use scoped provider readback. An exact known receipt settles the original record. Unknown results stay uncertain. Definitive no-send evidence can permit an ordinary Outbox retry with the same key. The one-use Effect claim remains consumed.
- Schema 004 preserves prior work and creates source-version backups on migration. The guarded restore entry point publishes a fresh private destination in persisted reconciliation-only mode. Restored grants and pending records stay inert across reopen. Scoped inspection, revoke, and exact readback remain available.
