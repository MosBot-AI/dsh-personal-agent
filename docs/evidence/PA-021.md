## Implemented boundary

- One foreground native DSH Web process holds the SQLite writer lease before native schedule resolution starts. Loopback public probes separate process liveness from readiness. The native owner link uses a private file and a current-process identifier. Diagnostic status, backup and audit use the authenticated inbox. The opt-in launchd and systemd descriptions invoke the same launcher.
- The watchdog observes the current Attempt and generation, records bounded diagnostic metadata, and separates stale progress, repeated tool calls, budget and provider conditions from process health. A heartbeat gap starts one bounded warm schedule scan. Abort fences further application writes by that scan. Exact native intent or receipts remain available for ordinary reconciliation.
- Provider authentication, rate, transient availability and model errors have distinct resource conditions. An uncertain admitted model request retains its budget evidence. The executor releases the Worker slot after native teardown. Owner resume rechecks the exact wait and budget. Late cancelled results leave other Workers and future routing authority intact.
- Online backup pins a committed SQLite snapshot, including sealed artifacts, and publishes an owner-private standalone file. Retention applies only to managed backup names after successful publication. Restoring an older snapshot holds dispatch in reconciliation-only mode. The owner audit exports scoped counts and fixed metadata with a bounded cursor. The default in-process diagnostic retention is 14 days and 512 records.

## Resident startup admission

[Maintenance issue #94](https://github.com/MosBot-AI/dsh-personal-agent/issues/94) reproduces a prepared Web profile that kept listening on main `917e84e` while the resident inbox failed to attach. The resident overlay now makes the pinned DSH Web startup entry depend on `dshpaCompute`, which the bundle provides after the resident inbox attaches. DSH's startup audit rejects the pending entry.

On Debian 13 with Node.js 24.14.1 and DSH 0.2.2-rc.1, three invalid launches with the bundle missing, the bundle disabled or the configured scheduler disabled remained alive through the baseline test deadline. All three exited with a nonzero status and left no owner link after the fix. Five resident cases and twelve ordinary Web cases passed. The valid resident host, duplicate-writer rejection, guarded restore-only inspection and generated Linux unit verification passed. The restored profile reported liveness 200 and readiness 503. Type checking, workspace builds, 329 keyless tests, 12 coordination tests, plan validation and whitespace checks passed.

Login service enrollment and physical-device lifecycle acceptance remain part of the release work.
