# 统一个人 Agent 客户端 API

[English](shared-client-api.md) | 简体中文

## 状态与权威来源

用户要求手机和电脑客户端使用同一套 REST 契约，并可选择 Hermes 或 DSH 作为后端。本次 DSH 首切片实现的是**经过认证的协议发现**，不是功能全面对齐，也不是新的 Agent 运行时。它扩展 [PA-022](https://github.com/MosBot-AI/dsh-personal-agent/issues/23)；已部署 HTTPS 和实体手机验收仍未完成。

0.1.0 契约的唯一权威来源是 `MosBot-AI/hermes-superagent/contracts/personal-api`。本仓库在 `contracts/personal-api` 中保存完全一致的 JSON Schema、OpenAPI 描述、测试夹具和摘要清单。来源锁文件记录审查分支上的权威提交 `48a930a2c01b2add9e349cbc1f0d65278066cc1c`；这不表示权威变更已合并或发布。必须先修改权威来源，独立审查后同步更新固定版本和复制的字节，再执行两端适配器的一致性测试。不得为了迁就某个实现而单独修改复制的 Schema。0.1.0 尚未稳定；破坏性协议改动需要明确协调迁移，不得悄悄重新解释 `/v1`。

## 已实现行为

- `GET /v1/capabilities` 使用已有移动设备 Cookie、严格 Host/Origin 检查、撤销机制和 no-store 响应。它返回统一的 `personal.api.v1` 信封、契约版本、用于诊断的后端 ID、能力、传输和限制。客户端应依据能力，而不是按后端名称分支。
- 七项统一领域能力目前均报告 `supported:false`、`enabled:false`、`available:false`、`reason:not_implemented`。已有原生或旧版移动功能不能证明新的统一操作已经存在。
- `GET /v1/tasks` 在验证当前设备身份后返回 HTTP 409，错误为 `capability_unavailable`，能力为 `tasks.list`。不查询或修改任务。在返回不可用结果前，验证支持的 `limit`（1–64）和有界不透明 `cursor` 参数；拒绝重复和未知参数。
- 公共错误区分认证（401）、来源被拒（403）、请求无效（400）、能力不可用（409）和暂时服务故障（503）。不返回凭据、原生会话或来源目的地。
- 可轮询普通 JSON 发现接口。`transport.polling:true` 不代表已有领域变更流：`changes.poll` 仍不可用。尽管不变的旧版 `/v1/events` 使用 SSE，统一 SSE 仍为 false。
- 一个尚未接入路由的纯任务投影将原生状态映射到统一状态。正在取消仍为等待，需要对账仍为未知，绝不映射为已完成或已取消。无法表示的 ID/标题和不安全的数值版本会被拒绝，不会悄悄截断或舍入。这是已测试的适配接口，不是已注册的任务列表实现。

配对、旧版任务快照、审批交接/响应和旧版 SSE 保留现有路由及语义。未引入替代登录签发器、令牌转发、通用工具执行、外部写入或新监听端口。移动监听器仍需显式启用，并使用操作者配置的 HTTPS 反向代理。


OpenAPI 的 `backendSession` Cookie 绑定仅描述当前已实现的 DSH HTTP 适配器，不是新签发器，也不表示 Hermes 使用同名 Cookie。客户端使用正常的 Cookie 容器，业务行为不得按后端品牌分支。

## 后续切片与兼容性差距

1. 增加有界、经过认证的统一任务列表，并明确实时分页及作用域语义。现有 64 条任务快照没有完整性或续页契约，不得冒充该集合。
2. 适配审批、操作和可轮询的持久变更流，保留精确一次性授权、版本检查、撤销和结果未知时的对账语义。
3. 会话续接和记忆必须通过已有原生所有者/运行时边界适配。每项操作在具备已验证的适配器及安全/恢复证据前，都必须保持能力不可用。
4. 用同一套客户端契约测试验证两端。Hermes 还需要已验证的 HTTP 主体传递；Schema 或 DSH 的成功不能解决该宿主接口缺口。原生手机登录和部署来源验收仍是独立发布门槛。

## 验证

`tests/api/shared-client.spec.ts` 将实际发现响应及任务不可用响应与权威夹具精确比较，验证复制文件的 SHA-256 摘要，覆盖所有原生任务状态映射，并通过真实回环 HTTP 验证认证、拒绝配对码作为凭据、设备撤销、严格 Host/Origin 和查询参数拒绝。`tests/api/remote.spec.ts` 保留旧版设备/回放覆盖。

这些检查使用隔离的本地合成状态，不能证明实体手机行为、已部署 HTTPS 来源、完整的统一任务访问或与 Hermes 的功能对齐。云工作区无法访问用户本地知识库，因此未从中推断历史决策。

- 统一与已有移动 API 测试：14/14 通过，包含真实回环 HTTP。
- 全工作区 `tsc --noEmit`、personal-agent 编译和客户端打包通过。计划验证、12 项协调测试和空白检查通过。
- 默认并行完整套件：332/336 通过；待修复 #75 的已知调度恢复竞态和三项媒体/恢复五秒超时失败。使用 `--maxWorkers=2` 后为 335/336，仅同一调度恢复断言失败。未放宽超时、断言或生产调度逻辑。本分支不包含待合并 #76。完整套件门槛仍未通过。
- 原生移动/浏览器套件无法通过 `dbus-run-session` 启动：当前环境拒绝临时目录和消息总线套接字。未修改任何安全设置。这是未运行阶段，不是手机或浏览器检查成功。
- 可用 pnpm 为 11.25.0，而非仓库固定的 11.28.5，安装因版本不符而拒绝。测试将已有相同锁文件的依赖安装复制到本工作树，直接使用其中固定的 TypeScript/Vitest 可执行文件。未修改包或锁文件版本。生成库尚未就绪时的首次完整套件失败，由上述构建后结果取代，不宣称首次运行通过。
