## 1. 持久化领域模型

| 记录 | 最少字段与不变量 |
| --- | --- |
| Owner/Profile | 稳定所有者 ID、已验证账户/设备关联、配置档案隔离、策略版本 |
| SourceEvent | 来源实例 + 外部事件 ID + 外部修订号作为唯一键；可信操作者元数据与不可信正文分离；发生/接收时间；线程和来源 |
| Conversation | 稳定的用户可见对话 ID、运行时会话引用、最后检查点、原始交付目的地 |
| Project | 所有者、标题、目的、资源引用、当前状态；不隐式授予对全部引用资源的访问 |
| Task | 所有者/项目、请求结果、约束、状态、版本、下一步、截止时间/时区、来源、验收条件 |
| Attempt | 任务、原生智能体/会话身份、代次、执行器、受限能力/数据范围、开始/结束/心跳、结果、产物引用 |
| Grant | 批准主体、动作/资源/账户/接收方/数据范围、限制、过期时间、审批证据、策略版本、撤销状态 |
| Approval/Question | 请求 ID、任务/执行尝试、类型、精确待执行动作或问题、安全显示文本、过期时间、状态、响应者；二者类型独立 |
| Effect | 稳定操作 ID、任务/执行尝试/代次、意图与载荷摘要、授权、提供商幂等键、状态、回执、核对数据 |
| OutboxItem | 目的地、脱敏载荷/产物引用、去重键、交付状态、回执、重试次数、下次尝试时间 |
| Artifact | 所有者、生成它的执行尝试、内容哈希、存储引用、媒体类型、来源、可见性和保留策略 |
| MemoryRecord | 所有者/范围、事实或引用、来源、有效性、明确/推断、置信度、替代/删除版本；永不作为授权依据 |
| Schedule | 所有者、任务/规则引用、时区、下次发生时间、本地时间意图、重复/错过执行策略、租约和最后结果 |

持久化时间点使用 UTC；涉及当地钟表时间含义时，保留 IANA 时区和原始用户意图。ID 不得编码秘密。在每个边界验证模式，并对迁移进行版本管理。

建议初期 SQLite 数据库作为工作和效果状态的权威来源。Markdown 导出是可读视图，不是第二套竞争性的任务数据库。索引和摘要属于派生数据。凭据位于独立秘密存储中，绝不进入执行智能体上下文或导出的任务记录。

## 2. 任务与执行尝试状态机

拟议任务状态：

```text
queued -> running -> verifying -> completed
             |-> waiting_input / waiting_approval / waiting_event
             |-> waiting_environment / waiting_resource
             |-> blocked / failed
nonterminal -> paused -> queued
nonterminal -> cancelling -> cancelled / reconciliation_required
wait or blocked -> queued (validated wakeup)
failed -> queued (explicit retry, new Attempt)
reconciliation_required -> completed / failed / cancelled (verified outcome)
```


这些转换需要明确且经过验证的事件。任务也可在运行前取消。失败任务只能通过新的执行尝试和经过检查的转换来重试；不能抹去先前失败。已完成/已取消任务不能仅因外部线程收到新消息而重新启动。

执行尝试有独立的运行时生命周期。`agent idle`、传输断开、模型轮次结束、业务任务完成和用户结果交付是不同事实。执行智能体若未提供必要产物或回执，其响应不能满足完成条件。

任务更新使用乐观版本控制。以事务持久化命令、状态变更以及效果/发件箱意图。首个部署可使用单进程锁；若以后增加分布式执行器，则必须使用租约和 fencing token，防止过时执行尝试提交新效果。

## 3. 拟议应用命令与事件边界

领域命令应独立于传输方式。本地 DSH 工具和未来 HTTP 适配器应调用同一服务，而非复制业务逻辑。

```ts
type CommandEnvelope = {
  commandId: string;          // 幂等范围限定为已认证所有者/客户端
  expectedVersion?: number;
  conversationId?: string;
  taskId?: string;
  type: string;
  payload: unknown;           // 通过命令模式验证
};

type PublicEvent = {
  eventId: string;
  sequence: number;           // 在获授权事件流内单调递增
  schemaVersion: number;
  occurredAt: string;
  conversationId?: string;
  taskId?: string;
  attemptId?: string;
  type: string;
  payload: unknown;           // 经允许列表筛选并脱敏的视图
};
```

已认证的所有者和设备来自可信适配器，而非可写的封装字段。以不同载荷复用 `commandId` 属于冲突，不是第二个动作。事件 ID 和任务 ID 不是授权令牌。

PA-022 首先复用原生 Remote；确有传输缺口时，HTTP/SSE 适配器使用以下拟议端点：

- `POST /v1/commands`：验证/入队命令，并返回其持久标识。
- `GET /v1/tasks` 与 `GET /v1/tasks/{id}`：获授权的任务投影视图。
- `POST /v1/tasks/{id}/cancel`：请求取消并返回当前转换状态，而非虚假的最终结果。
- `POST /v1/approvals/{id}/responses`：带预期请求版本的精确审批响应。
- `GET /v1/events?cursor=...`：已脱敏且可回放的 SSE 事件流。
- `GET /v1/snapshot`：游标过期/有缺口后的恢复。

建议公共事件包括 `task.updated`、`attempt.progress`、`approval.requested`、`question.requested`、`artifact.ready`、`effect.reconciliation_required` 和 `delivery.failed`。流式 token 增量可以是临时数据；权威任务事件必须持久化。未经保留/游标行为测试，不应声称重连无损。

远程访问使用 TLS、明确认证、限定范围的设备访问、速率限制，以及适合所选认证模式的 CSRF/来源保护。仅限本地的服务默认绑定回环地址。对已认证所有者/配置档案之外的所有任务/产物/事件流读取默认拒绝。

## 4. 授权与审批

分离两道关卡：

1. **接入关卡：** 该已验证操作者/来源是否有权请求或触发此项工作？
2. **动作关卡：** 现在是否允许使用这个账户、接收方、资源、数据、范围和当前授权执行这个精确动作？

LLM 提议动作。确定性的可信代码检查授权和执行约束。工具元数据、检索文档、引用消息、执行智能体交回结果和记忆均不能批准动作。

审批必须绑定批准者、请求/任务/执行尝试、动作类型、目的地/资源、规范化载荷摘要、数据披露、限制、策略版本和过期时间。任何实质变化都会令审批失效或要求重新评估。来自其他用户/设备/会话的审批应拒绝，除非该身份已获明确授权。

派发必须使用摘要已获批准的不可变权威载荷。将一次性审批的预留或消耗与唯一效果派发声明绑定为原子操作；并发响应或重试不能复用审批来执行多个效果。拒绝审批与派发之间的载荷修改。

持久化待审批事项和问题，但不能假设宿主内存中的旧审批 promise 可跨重启存续。恢复时必须重新验证待执行动作、构建新的原生执行路径，并核对是否已发生效果。澄清回复不等于批准外部写入。

撤销在执行边界生效，并使已排队效果失效。区分软暂停、任务取消、授权撤销和紧急停止。可信进程内代码必须充分串行化或隔离最终授权检查与派发，防止队列中使用过时授权；对于不可避免的在途效果，应如实记录。

## 5. 工具、连接器与插件安全

- 主智能体和执行智能体均采用最小权限。执行智能体继承任务授权的子集，绝不获得更宽范围。
- 原生工具 guard 能提供所需强制执行时，应使用 DSH guard；证明覆盖范围，不要假设提示词或工具列表就是隔离。
- 受限 shell 不能借环境凭据访问同一 API，绕过被拒绝的连接器动作。敏感连接器执行智能体应禁用通用 shell，除非存在真正的沙箱和凭据边界。
- 将第三方 MCP 服务器和工具视为不可信。验证参数和输出，限制响应大小，防止动态工具变化悄然扩大权限。
- 账户凭据保存在代理或秘密存储中。执行智能体仅在必要时获得短期/限定范围的访问；避免令牌出现在日志、进程参数、产物或模型提示词中。
- 验证 URL 和重定向；限制抓取器的外连和内网访问；防止文件路径穿越和符号链接逃逸；验证上传/下载类型及大小。
- 检索前和输出前执行所有者/配置档案/资源标签检查。私人邮件与公共仓库有关联，不等于获准把邮件复制到评论中。
- 模型提供商也会接收数据。即使是只读任务，也要在推理、传输检索上下文、压缩和摘要之前应用目的地/数据策略。提供商回退不能悄然将个人上下文发送给另一个提供商。这项基础保护不取决于是否选择模型路由选项 O1。
- 仅可信且经过审查的插件可在 DSH 进程内运行。插件清单或依赖注入边界无法约束以同一操作系统用户执行的恶意代码。

## 6. 取消与外部效果

取消流程：

1. 持久化 `cancel_requested`，推进任务代次/撤销状态。
2. 阻止该执行尝试/范围的新派发和新效果。
3. 对所绑定智能体及相关子工作调用原生 DSH 取消路径。
4. 核对可能仍在运行的工具/作业和任何外部副作用。
5. 只有具备终止/效果证据时才标记已确认取消；否则显示 `cancelling` 或 `reconciliation_required`。

原生智能体取消不会撤回已发送消息、已接受预订或已提交文件写入。只能补偿时不要声称可回滚。重复取消请求应具备幂等性，且不能取消无关任务。

拟议效果状态：

```text
prepared → authorized → dispatching → confirmed
                         ├── failed
                         └── uncertain → confirmed / failed / manual_reconciliation
```

派发前写入意图，之后持久化回执。优先采用提供商幂等键。如果传输后发生网络超时，重试前按操作/回执查询提供商。若既无幂等支持，也无可靠查询，则停留在不确定状态。仅本地去重键不能保证远程系统恰好执行一次。

发件箱接受、提供商接受、实际交付和接收方已读是独立状态。如果提供商只报告接受，就展示该事实，不声称已交付。

## 7. 恢复、迁移与隐私

启动时：获取受支持的运行时锁；安全迁移；加载非终态任务；检查原生会话/智能体状态；核对派发中效果；恢复等待中的问题/审批；然后恢复符合条件的计划和发件箱交付。不要盲目重跑所有标记为运行中的任务。

使用带退避和随机抖动的有限重试。分别分类认证、提供商永久拒绝、速率限制、暂时网络故障、模型失败、本地状态损坏和外部结果不确定。看门狗可检测卡住的执行智能体，但不能扩大其权限，也不能重启用户已取消的工作。

备份需具备加密/访问控制、经测试的恢复路径、成文的保留策略和删除策略。迁移应保留回执及审计历史，提供迁移前备份，并在失败时不悄然删除未知记录。对于破坏性模式变更，应说明回滚是否需要从备份恢复，不要假装所有迁移均可逆。

恢复旧备份可能丢失已在远程执行动作的回执、取消和撤销记录。恢复后进入仅核对模式：暂停外部写入、计划和发件箱派发；刷新当前授权；在启用执行前核对快照之后的不确定事项。恢复的旧授权或待发消息不得自动重新生效。

删除记忆时，应移除当前记录、检索索引项和派生事实/摘要，或标记删除，确保不会重新引入。说明备份保留和不能立即擦除的审计记录。绝不将账户秘密保存在记忆中。

## 8. 必需测试矩阵

| 领域 | 故障或场景 | 预期证据 |
| --- | --- | --- |
| 原生契约 | 宿主升级、创建/恢复、取消/流式/guard 钩子 | 固定版本测试；拒绝不兼容宿主 |
| 身份 | 伪造显示名、引用所有者请求、错误配置档案/设备 | 不创建所有者授权；拒绝跨配置档案读写 |
| 去重 | Webhook/轮询重叠、重复命令、同 ID 不同载荷 | 一个逻辑操作或明确冲突 |
| 并发 | 竞争更新和过时执行结果 | 版本/代次隔离拒绝过时修改 |
| 审批 | 拒绝、过期、参数变化、过时卡片、待审批时重启 | 无效审批下不执行动作 |
| 一次性审批 | 同时响应/派发、审批后修改载荷 | 仅一个不可变的已批准效果；拒绝重复消耗和载荷变化 |
| 撤销 | 入队后派发前撤销；执行中停止 | 阻止新效果；核对在途结果 |
| 工具隔离 | 其他 shell/MCP 路径、含秘密环境、路径逃逸 | 被禁止效果不能绕过可信关卡 |
| 崩溃恢复 | 发送前崩溃、发送后回执前崩溃、回执后任务更新前崩溃 | 不盲目回放；任务/效果状态一致 |
| 交付 | 429、渠道永久失败、已接受但未确认交付 | 正确重试策略和真实交付状态 |
| 记忆/上下文 | 反复压缩、中文查询、更正、删除、重启 | 相关且有来源的召回；已删除事实不复活 |
| 数据共享 | 私有来源与公共任务相关 | 无匹配披露授权时拒绝/脱敏输出 |
| 模型数据披露 | 为摘要或提供商回退发送上下文 | 传输前执行目的地/数据策略 |
| 调度器 | 夏令时、时区变化、错过执行、重复唤醒 | 按意图发生一次，或有记录的补执行行为 |
| 客户端（若选定） | 重连、游标过期、重复审批响应 | 快照恢复、不重复动作、事件流隔离 |
| 语音（若选定） | 插话、STT 误识别、断线、TTS 失败 | 文本回退，不意外批准/取消 |
| 运维 | 迁移失败、磁盘满、索引损坏、备份恢复 | 安全降级，权威记录可恢复 |
| 旧备份恢复 | 快照早于发送、撤销或取消 | 以仅核对模式启动；不自动回放或重新激活过时授权 |

单元测试证明纯状态转换；宿主契约测试证明 DSH 集成；故障测试证明恢复；真实模型/提供商测试证明完整路径。它们不能相互替代。各里程碑记录命令、版本、夹具/实时分类、结果及未测试限制。

## 9. 有效完成声明的定义

主智能体应报告变更内容、结果查看位置和任何剩余不确定性。“已实现”需要代码；“已测试”需要具名且已执行的检查；“已发布”需要验证远程状态；“已交付”需要该渠道可获得的提供商证据。仅有设计文档不满足前三类实现声明中的任何一类。

## 10. 实施级不变量与接口

以下细则约束 PA-003 之后的实现。它们是拟议应用契约，不是现有 DSH API。

### 新增记录

| 记录 | 必需字段和不变量 |
| --- | --- |
| Project | `kind: project/goal`、成功条件、计划版本、里程碑、复查周期；目标拆解仍创建普通 Task |
| Subscription | 来源/线程/任务、`context/work` 模式、版本；context 不能授予权限或重启终态任务 |
| Task wait | 原因、精确事件/设备/资源/问题引用、截止时间、恢复条件；等待不占 Worker 槽 |
| Routine | 用户意图、版本、原生 schedule 映射、启用模式、授权、错过执行策略；应用意图只有一个权威记录 |
| Occurrence | routine ID + revision + 原定发生时间；原生重复投递仍只有一个逻辑执行 |
| Budget reservation | owner/task/provider、估算上限、币种、价格版本、实际用量、已结算/不确定状态；调用前原子预留 |
| Skill candidate | 版本、输入/输出、能力引用、成功实例、评测、激活/回退状态 |
| MediaJob | task/attempt/generation、后端实例和句柄、输入/工作流/模型哈希、输出规格、资源租约和结果；提交不明不盲重试 |
| ResourceLease | environment/resource ID、持有者、代次、到期时间、范围；桌面只有一个控制者，每次输入由服务端校验 |
| CredentialRef | 不透明 ID、后端、非秘密元数据、允许的账号/域名/用途；领域数据库不存秘密值 |
| SecretInputRequest | owner/device/task revision、凭据类型、保存方式、允许来源/用途、到期、单次 nonce、状态；原始输入绕过对话 |
| DesktopSession | owner/device/environment、查看/控制权限、到期、控制租约和连接状态；客户端标记不是授权 |

实现使用具名类型 ID，不能将不同 ID 作为可互换字符串。运行时校验在模型/工具/config/file/queue/process/wire 边界执行；已具备静态类型的同进程值不必仅因不信任 TypeScript 而重复校验。

### 状态转换与并发

- `ready` 是 Worker 回报，触发 `verifying`；只有必需产物和效果验证通过后才进入 `completed`。
- 所有者新回复唤醒工作前重新检查授权、代次和任务版本。第三方上下文不能复活取消/完成任务。显式 `work.reopen` 创建新 Attempt，保留过去历史。
- `paused` 停止新派发，不声称回滚在途效果；resume 重查授权/预算。取消还需撤销任务代次并核对所属执行。
- 等依赖用 `blocked` 和 `reason=dependency`；拒绝依赖环。精确依赖完成可唤醒一次；依赖失败不能把下游任务标成完成。
- 每个 Task 最多一个活动顶层 Attempt。Worker 可拥有 DSH 子智能体，但纳入其预算/资源限制。共享文件、分支或浏览器的执行器必须使用显式租约或独立 worktree/profile。
- 停止和审批响应走确定性服务及前台保留容量，确认接收不需要模型调用。

### 事务与跨存储交接

必需唯一键：`(ownerId, clientId, commandId)`、`(sourceInstanceId, externalEventId, externalRevision)`、`(routineId, routineRevision, occurrenceAt)`、`effect.operationId`，以及顶层尝试的 `(taskId, generation)`。同 command ID 不同规范化载荷返回冲突。来源适配器必须给出稳定 revision，或明确把更新视为新事件。

命令事务读取预期版本、验证转换、存事件/结果，并添加效果与发件箱意图后提交；网络操作在提交后执行。一次性审批预留与不可变效果声明原子提交。授权检查和派发交接与撤销串行化；不可避免的在途动作保留核对路径。

产品 SQLite 与 DSH Session 存储不能共享一次原子提交。使用持久交付意图和唯一输入 ID 衔接；Session flush 后再存确认。重启时比较 Session 已消费/待消费输入 ID，核对后决定重投。PA-002/009 必须验证固定宿主是否可观察这些状态；存在缺口则增加最小扩展点，不宣称天然恰好执行一次。

原生 schedule 注册也跨提交：先存映射意图，再记录/核对创建出的 schedule ID；重复投递使用同 Occurrence 键。run-now 使用独立 command ID。在途提醒保留原 revision，并检查当前启用/撤销状态。

### 初始配置语义

Worker 默认并发 2，保留独立控制处理容量；E02 基准配置为 4。GPU 重任务初始并发 1；桌面控制互斥。这些是经过校验的插件配置，不是藏在代码里的常数。无人值守付费工作需要明确每日/单任务上限及已知价格或保守估算上界，否则不启用；未知价格不计为零。

上下文预算根据模型容量和输出预留计算。扣除固定指令与当前输入后，初始比例为权威状态 30%、近期对话 25%、检索 25%、记忆/检查点 20%，先裁剪低优先级内容。这是可调初值，不是质量承诺；超长证据用稳定引用外置。

初始保留策略：任务/成果保留至用户删除，详细诊断日志 14 天，自动事实提取和屏幕录像默认关闭。说明存储增长并允许配置；备份保留、删除标记需在恢复时执行。不得将日志变成隐藏的第二个个人记忆库。
